# Agrileaf Leave Management System — instructions for AI coding sessions

## Canonical architecture

This is the **only** architecture for this application. Do not introduce anything else.

| Layer | Technology |
|---|---|
| Frontend | React + TypeScript + Ant Design (Vite), in `frontend/` |
| Backend | Django + Django REST Framework, in `backend/` |
| Database | PostgreSQL (`backend-db` service) |
| Infrastructure | Docker / Docker Compose (`docker-compose.backend.yml` for local dev, `docker-compose.backend.prod.yml` for UAT/production) |

See [`README.md`](./README.md) for how to run it and [`DEPLOYMENT.backend.md`](./DEPLOYMENT.backend.md)
for the full deployment guide.

## Rules for any change in this repository

- **Do not introduce Next.js.** The frontend is React + TypeScript + Ant Design via Vite, full stop.
- **Do not introduce Drizzle** (or any other ORM). The backend is Django's own ORM against PostgreSQL.
- **Do not recreate the old architecture** in any form, even partially.
- **Do not create a second frontend or a second backend.** There is exactly one of each:
  `frontend/` and `backend/`.
- **Do not replace existing functionality unnecessarily.** A bug fix doesn't need a rewrite; a
  small feature doesn't need a new architecture.
- **Preserve existing database/data.** Never drop the database, reset migrations, or run
  destructive commands (`flush`, `migrate zero`, etc.) against real data. Migrations are
  additive — `backend/entrypoint.sh` runs `python manage.py migrate --noinput` automatically on
  every container start; don't work around or bypass this.
- **Prefer modifying the current implementation over rebuilding it.** If something looks wrong,
  fix that specific thing — don't regenerate a page, an app, or a service from scratch as a first
  resort.
- **Follow the existing API architecture.** One Django app per domain area (see `backend/`'s app
  list in `README.md`), REST endpoints under `/api/<app>/`, business logic in each app's
  `services.py` (not the view), permissions via `IsAdminRole`/`IsAuthenticated`, and a
  `frontend/src/lib/api-client.ts`-mediated call from the React side — match the pattern already
  established in the app you're touching rather than inventing a new one.
- **Run validation after changes.** Frontend: `npx tsc -b`, `npx vite build`, `npx vitest run`
  (all from `frontend/`, exact commands in `README.md`). Backend: `python manage.py check` and
  `python manage.py test` (inside the `backend` container). Both `backend/` and `frontend/` are
  built with `COPY . .` at image-build time — no bind mount — so **rebuild the relevant Docker
  image after every source change** before it takes effect:
  `docker compose -f docker-compose.backend.yml build backend` (or `frontend`), then
  `up -d backend` (or `frontend`).
